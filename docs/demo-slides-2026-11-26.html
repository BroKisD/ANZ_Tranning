2 · How it is built

Security: protected, and accepted for now

What keeps it safe today, and what we knowingly left open.

Protected

  • No stored Google keys. GitHub signs in with short-lived tokens, only for the owner's repos.
  • GitHub tokens are encrypted (AES-256-GCM). The key is in Secret Manager. Tokens never reach logs or replies.
  • Per-app webhook secrets are Actions secrets, never committed.
  • Values written into generated files are checked. Live links must be https.
  • A person approves the pull request before anything is merged.

Accepted for now

  • highOne shared API key and a user header, not real sign-in
  • highOne deploy account for every app, set up by hand. A trusted repo could replace any service, even the platform.
  • mediumEvery app is public: no abuse checks or quotas
  • mediumA personal token per user is long-lived. A GitHub App gives short, per-repo tokens.
2 · How it is built

The orchestrator today

The part that drives every project: one goroutine per project.

API callSaves the project, starts a goroutine, answers right away
→
pendingCompare-and-set to generating. A second run does nothing.
→
generatingCreate repo, generate code, open the PR. 5 min limit per step.
→
waitingAn in-memory channel. Times out after 24 h.
→
deployingMerge, then poll GitHub every 5 s. 15 min limit.
→
success / failedStatus and live link saved in MySQL

Durable: MySQL

  • Status, step, repo, PR and live link
  • Moved forward only, with compare-and-set
  • What the API and the script read

Only in memory

  • The goroutine that runs each project
  • The approval channel
  • The polling loop. A restart loses all three. A watchdog marks stale deploys failed.

The target architecture

Temporal runs each project and listens for the GitHub Actions result. If the deploy fails, the logs go back to Claude, which patches the PR and tries again.
